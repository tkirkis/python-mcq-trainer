# S8 — Web applications

## Clients, servers and the network {#web-architecture}

- A **server** is a program that keeps running and can be reached through the network; the word also names the machine that runs it. The program that sends requests (your browser, `curl`, a Python script) is the **client**.
- Your computer is not plugged directly into the internet: it goes through an **ISP** (Internet Service Provider), which is itself connected to the internet. Only servers and ISPs are connected directly.
- Every machine on the network has an **IP address**, like a postal address. IPv4 = 4 numbers separated by dots, **each 0–255** (one byte). `89.259.29.11` is NOT valid (259 > 255); `127.0.0.1` is valid.
- `127.0.0.1` (hostname `localhost`) is the loopback address: it always means *your own computer*.
- **DNS resolution** turns a domain name (`github.com`) into an IP address. The ISP keeps a name → IP table and asks other nodes recursively when it does not know a name. This happens on the client side, *before* connecting.
- One machine can run several servers (web, API, mail, database). The **port** selects which program receives the request: each server listens on its own port (HTTPS → 443).
- Then a **TCP connection** is opened to `IP:port`, and the HTTP request/response travel over it.
- A large response is split into **packets** that may take different routes; the **client** reassembles them once it has received them all.

```text
https://github.com/tensorflow
1. DNS: github.com -> 140.82.118.4
2. TCP connection to 140.82.118.4:443   (443 = default for https)
3. HTTP request  (GET /tensorflow)
4. HTTP response (status + headers + HTML, sent in packets)
5. Browser renders the HTML (and sends more requests for images, AJAX...)
```

```python
import ipaddress
ipaddress.ip_address('127.0.0.1').is_loopback   # True
ipaddress.ip_address('89.259.29.11')            # ValueError: 259 > 255
```

## HTTP requests and responses {#http}

- HTTP is a **request/response** protocol: the client sends a request, the server answers with a response. The server never speaks first.
- A **request** contains the **method**, the URL/path and headers such as `Host` (domain asked for), `User-Agent` (which client), `Accept-Language`, `Cookie`.
- Methods: **GET** retrieves (what the address bar sends), **POST** sends data (form submission), **PUT** creates/replaces, **DELETE** removes. The method lives in the *request*, never in the response.
- A **response** contains a **status**, headers (`Content-Type`, `Content-Encoding`, `Set-Cookie`, `Server`, `Date`) and the **body** (HTML for a web page, serialized data for an API).
- `Content-Type: text/html; charset=utf-8` = the body is HTML encoded in UTF-8; `application/json` = JSON data. Compression is `Content-Encoding` (gzip), not Content-Type.
- `Set-Cookie` and `Server` are **response** headers; `Host` and `User-Agent` are **request** headers.
- The **browser renders** the HTML into a page. While rendering it sends further requests: one per image, plus **AJAX** calls (asynchronous HTTP requests made from JavaScript). Page with 3 different images = 1 + 3 = 4 requests.
- Status classes: 2xx success, 3xx redirection, 4xx client error, 5xx server error. An exception inside a Flask handler → **500**.

| Code | Phrase | Meaning |
|---|---|---|
| 200 | OK | success |
| 201 | Created | resource created |
| 301 | Moved Permanently | permanent redirect |
| 302 | Found | temporary redirect (Flask `redirect()` default) |
| 400 | Bad Request | malformed request |
| 401 | Unauthorized | not authenticated |
| 403 | Forbidden | authenticated but not allowed |
| 404 | Not Found | no resource / no route for this path |
| 405 | Method Not Allowed | route exists, method not accepted |
| 500 | Internal Server Error | the server crashed while answering |

```python
from http import HTTPStatus
HTTPStatus(404).phrase        # 'Not Found'
HTTPStatus.OK.value           # 200
HTTPStatus.NOT_FOUND == 404   # True (IntEnum)
```

## URL anatomy {#urls}

- General form: `scheme://username:password@host:port/path?query#fragment`. Order matters: user info before `@host`, port after the host, query (`?`) before fragment (`#`).
- **Scheme** = protocol: `http`, `https` (encrypted), `ftp`, `file`, `mailto`...
- **User info** (`user:password@`) is rarely used on the web, more for database connections.
- **Host** = domain name, subdomain or IP address. **Port** selects the program; when omitted the default of the scheme is used.
- **Path** = the route on the server; each route is handled by a function (a *handler*).
- **Query** = the handler's arguments: `name=value` pairs separated by `&`, escaped (a space becomes `+`).
- **Fragment** (`#...`) is **never sent to the server**: the browser uses it to scroll to a part of the page.
- `urlparse` does not fill in default ports: `urlparse('https://x.com/').port` is `None`. An explicit port is returned as an `int`. `netloc` includes user info and port; `hostname` is just the host.

| Service | Default port |
|---|---|
| HTTP / HTTPS | 80 / 443 |
| SSH | 22 |
| SMTP / SMTPS | 25 / 465 |
| DNS | 53 |
| MySQL | 3306 |
| MongoDB | 27017 |
| Redis | 6379 |
| `python -m http.server` | 8000 |

```python
from urllib.parse import urlparse, parse_qs, quote_plus, urlencode
u = urlparse('http://127.0.0.1:5000/custom/Ana?lang=fr#top')
u.hostname, u.port, u.path, u.query, u.fragment
# ('127.0.0.1', 5000, '/custom/Ana', 'lang=fr', 'top')   <- no '?' / '#'
parse_qs('q=ip+address&lang=en')   # {'q': ['ip address'], 'lang': ['en']}  (lists!)
quote_plus('ip address')           # 'ip+address'   (quote() gives 'ip%20address')
urlencode({'q': 'ip address', 'page': 2})   # 'q=ip+address&page=2'
```

## The requests package and command-line clients {#requests-lib}

- `resp = requests.get(url)` sends a GET request and returns a `Response`; `requests.post(url, data=...)` sends a POST with data.
- `resp.status_code` is the integer status (200, 404...). `resp.ok` is only a bool (True if < 400). There is no `resp.status` / `resp.code`.
- `resp.text` is the body as a **str**, decoded with the charset declared in the `Content-Type` header (for `text/*` without a charset, requests assumes ISO-8859-1); `resp.content` is the raw **bytes** (use it for images/binary files). With non-ASCII text, `len(resp.content)` can be larger than `len(resp.text)`.
- `resp.json()` deserializes a JSON body into Python objects (`dict`, `list`, `True`, `None`...).
- `params={...}` builds the query string for you, escaping values.
- Large downloads can be streamed in chunks instead of one big response.
- `wget` and `curl` send HTTP requests from the terminal and return the raw HTML: **no rendering**. Handy to test a server; `curl` makes POST requests easy.

```python
import requests
req = requests.Request('GET', 'https://www.google.com/search', params={'q': 'ip address'})
req.prepare().url    # 'https://www.google.com/search?q=ip+address'  (nothing sent)

resp = requests.get('https://en.wikipedia.org/wiki/Abraham_Lincoln')
resp.status_code     # 200
type(resp.text), type(resp.content)   # (str, bytes)
```

## Flask web servers {#flask}

- Web frameworks (Django, Flask, Bottle, Pyramid, CherryPy, Tornado, Web2Py) let you write **handlers**: functions that build the HTTP response for a route. The handler returns the response body.
- `app = flask.Flask(__name__)` creates the app, named after the current module.
- `@app.route('/path')` is a **decorator**: `@d` above `def f` means `f = d(f)`, so it is `index = app.route('/')(index)`. A decorator is a function taking a function (and returning one).
- Route variables: `@app.route('/custom/<name>')` passes the matching part of the path as the argument `name`. `/custom` alone does not match → 404. `<int:item_id>` converts to `int`; a non-integer part does not match → 404.
- Return values: a **str** → 200, `text/html; charset=utf-8`; a **dict** → JSON, `application/json`; a tuple `(body, 201)` sets the status.
- Unknown path → **404**. Route declared with `methods=['POST']` and called with GET → **405** (without `methods=`, a route accepts only GET, plus the automatic HEAD/OPTIONS). Exception in a handler → **500**.
- `flask.redirect('/')` → **302** with a `Location` header; a browser (or `follow_redirects=True`) then requests `/`.
- Query parameters are read with `flask.request.args.get('q')` (decoded, `None` if absent).
- Templates: generic HTML with placeholders `{{person}}`, filled by `render_template('hello.html', person=name)` (files in `templates/`) — the template engine is Jinja.
- `app.run(port=5000)` serves on your own machine: `http://localhost:5000/` = `http://127.0.0.1:5000/`. Run it with `python3 app.py`. For tests use `app.test_client()` (no network, no `app.run`).

```python
import flask
app = flask.Flask(__name__)

@app.route('/custom/<name>')
def custom(name):
    return 'Hello {}'.format(name)

@app.route('/buy', methods=['POST'])
def buy():
    return {'sold': 'gums'}          # dict -> JSON response

c = app.test_client()
c.get('/custom/Ana').get_data(as_text=True)   # 'Hello Ana'
c.get('/custom').status_code                  # 404
c.get('/buy').status_code                     # 405 (GET on a POST-only route)
```

## Serialization for the web {#web-serialization}

- An HTTP body is always a string (or bytes). Turning data into such a string is **serialization**; rebuilding the objects is deserialization.
- An **API server** returns serialized data (usually JSON) instead of an HTML page.
- **JSON**: text, human readable, language-independent. `json.dumps(obj)` → str, `json.loads(s)` → objects; `json.dump`/`json.load` work with files.
- JSON types: object, array, string, number, `true`/`false`, `null`. So `True` → `true`, `None` → `null`, tuples → arrays (come back as **lists**), dict keys → **strings** (`1` → `"1"`).
- Sets are not JSON serializable → `TypeError`.
- **pickle**: binary, Python-specific, serializes almost any Python object (even functions by reference). `pickle.dumps` → bytes; files must be opened in `'wb'`/`'rb'`.
- A JSON round trip may not give back an equal object (tuple → list, int key → str key).

```python
import json
json.dumps({1: (2, 3)})                  # '{"1": [2, 3]}'
json.dumps({'c': True, 'd': None})       # '{"c": true, "d": null}'
data = {'a': (1, 2), 3: 'x'}
json.loads(json.dumps(data))             # {'a': [1, 2], '3': 'x'}  != data
```

## Exam traps checklist {#traps}

- An IPv4 number above 255 (e.g. `89.259.29.11`) makes the address invalid.
- `localhost` = `127.0.0.1` = your own machine; not `0.0.0.0`.
- DNS resolution happens on the client side, before any connection.
- Packets are reassembled by the client (the receiver), not the server.
- `http://` without a port → 80; `https://` → 443. MySQL 3306, MongoDB 27017, Redis 6379, DNS 53, SSH 22, SMTP 25.
- `urlparse(...).port` is `None` when no port is written, and an `int` otherwise.
- `u.query` has no leading `?`; `u.fragment` has no leading `#`; `u.netloc` includes `user:pass@` and `:port`.
- `parse_qs` returns lists of values; `+` is decoded as a space.
- `quote_plus` → `+` for spaces; `quote` → `%20`.
- The fragment is never sent to the server.
- The HTTP method is in the request; the status code is in the response.
- `Set-Cookie` is a response header; `Host`/`User-Agent` are request headers.
- 302 = Found (temporary, Flask `redirect` default); 301 = Moved Permanently. 401 = Unauthorized, 403 = Forbidden.
- 404 = no route matches; 405 = route matches but not the method; 500 = handler raised.
- `/custom` does not match `/custom/<name>`; `<int:id>` with a non-integer gives 404, not an error.
- A handler returning a dict gives `application/json`; a string gives `text/html`.
- `resp.status_code` (int) vs `resp.ok` (bool); `resp.text` (str) vs `resp.content` (bytes).
- wget/curl do not render pages; the browser does.
- JSON round trip: tuples → lists, int keys → str keys; sets → TypeError.
- `@app.route('/')` above `def index` = `index = app.route('/')(index)`.
