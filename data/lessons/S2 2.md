# S2 — Functions & data structures

## Function arguments {#function-arguments}

- A call binds arguments to parameters **positionally** (left to right) or **by keyword** (`name=value`); keyword arguments can be written in any order.
- In a call, every positional argument must come **before** the keyword arguments: `f(1, b=2, 3)` is a `SyntaxError`.
- In a `def`, ordinary parameters with a default value must come **after** those without one: `def f(a=1, b)` is a `SyntaxError` (only keyword-only parameters, after `*`, escape this rule).
- Omitting a parameter that has no default → `TypeError` (missing required argument). Too many arguments → `TypeError`.
- Giving the same parameter twice (`f(2, a=3)`) → `TypeError: got multiple values for argument 'a'`.
- A misspelled keyword (`heigth=3`) → `TypeError: unexpected keyword argument`.
- A default value is evaluated **once**, when the `def` runs, not at every call.
- Functions are objects: they can be passed as arguments, stored in lists, and called later. Pass `f`, not `f()` - `f()` passes its *result*.

```python
def dichotomy(func, a=-10, b=10, eps=1e-6):
    return func(a), b, eps

dichotomy(abs)                   # (10, 10, 1e-06)  defaults used
dichotomy(abs, eps=0.1, b=2)     # (10, 2, 0.1)     keywords in any order
dichotomy(abs(3))                # TypeError: 'int' object is not callable
```

```python
x = 10
def f(a=x):       # default computed now: a = 10
    return a
x = 20
f()               # 10
```

## Program flow {#program-flow}

- `def` only **defines** a function; its body runs when the function is called.
- The execution order follows the calls, not the order in which the code is written.
- Inside a function body, names (other functions, variables) are looked up **when it runs**, so `f` may call a `g` defined later in the file, as long as `g` exists at call time.
- Each call is pushed on the **call stack** (Last In, First Out): it remembers the arguments and where to return.
- When a call finishes, execution resumes in the caller just after the call; pending calls resume in reverse order.
- Functions can call each other (mutual recursion), e.g. `f → g → f → h → f ...`.

```python
def down(n):
    if n == 0:
        return
    print(n, end=' ')
    down(n - 1)
    print(n, end=' ')   # runs when the inner call returns

down(3)                 # 3 2 1 1 2 3
```

## Lists {#lists}

- Mutable, ordered sequences; may mix types and contain other lists (`[1, [2, 3]]` has **2** elements).
- `append(x)` adds **one** element (a list becomes a nested element); `extend(iterable)` adds each element (`extend('yz')` adds `'y'`, `'z'`).
- `insert(i, x)` inserts **before** index i; an index past the end just appends; `insert(-1, x)` goes before the last element.
- `pop()` removes **and returns** the last element; `pop(i)` the element at i; bad index → `IndexError`.
- `remove(x)` deletes the **first** occurrence of the value x; missing value → `ValueError` (not KeyError).
- `index(x)` gives the first position (`ValueError` if absent); `count(x)` counts occurrences.
- `sort()` and `reverse()` work **in place** and return `None`; `sorted(l)` returns a new list. `reverse()` does not sort.
- `+` concatenates two lists into a **new** list (`[1] + 2` → `TypeError`); `* n` repeats the elements.
- `x in lst` checks top-level elements only; `lst[len(lst)]` → `IndexError`.

```python
users = ['Ann', 'Bob']
users.append(['Cid', 'Dee'])
len(users)                # 3   (the list is one element)
[0, 1] * 3                # [0, 1, 0, 1, 0, 1]
```

```python
nums = [3, 1, 3, 2]
print(nums.sort())        # None   (sorted in place)
nums                      # [1, 2, 3, 3]
nums.remove(3)            # nums is now [1, 2, 3]  (first 3 only)
nums.pop(), nums          # (3, [1, 2])
```

## Slicing {#slicing}

- `seq[start:stop:step]`: start included, stop **excluded**; default step is 1.
- Omitted bounds mean "from the beginning" / "to the end" (`stop` defaults to `len(seq)`, not `len()+1`); with a negative step they are the two ends taken in reverse.
- Slices never raise: out-of-range bounds are clipped (`[1, 2][5:]` → `[]`), and `l[4:1]` with a positive step is `[]`.
- `l[::-1]` is a reversed **copy**; `l[:]`, `list(l)` and `l.copy()` are shallow copies.
- A slice of a list is a list, of a tuple a tuple, of a string a string.
- Slice assignment replaces a segment and may change the length: `l[1:4] = ['x']`; `l[1:1] = [7, 8]` inserts; `l[2:5] = []` deletes.
- An **extended** slice (with a step) must receive exactly as many values as it selects, otherwise `ValueError`.
- `del l[::2]` deletes every second element.

```python
l = list(range(8))
l[6:1:-2]          # [6, 4, 2]
l[::2][::-1][1:3]  # [4, 2]
l[2:5] = [20, 30]  # l is now [0, 1, 20, 30, 5, 6, 7]
l[::2] = ['a']     # ValueError: 4 slots, 1 value
```

## enumerate and zip {#enumerate-zip}

- `enumerate(seq)` yields `(index, element)` pairs, index first, starting at 0.
- `enumerate(seq, start=1)` (or `enumerate(seq, 1)`) only changes the first counter value; no element is skipped.
- `zip(a, b)` yields tuples `(a[i], b[i])` and stops at the **shortest** iterable (no padding, no error).
- `enumerate` and `zip` return one-shot iterators: a second `list(z)` gives `[]`.
- `dict(zip(keys, values))` builds a dict; `zip(*rows)` transposes rows into columns.
- Equivalent loops: `for i, x in enumerate(l)` ⇔ `for i in range(len(l)): x = l[i]`.

```python
list(enumerate(['a', 'b'], start=1))   # [(1, 'a'), (2, 'b')]
list(zip([1, 2, 3], 'xy'))             # [(1, 'x'), (2, 'y')]
z = zip([1, 2], [3, 4])
list(z), list(z)                       # ([(1, 3), (2, 4)], [])
```

## Tuples {#tuples}

- Immutable sequences: indexing, slicing, `len`, `in`, `count`, `index` work; `t[0] = ...` / `del t[0]` → `TypeError`; `t.append(...)` → `AttributeError`.
- The **comma** makes the tuple: `(5)` is an int, `(5,)` and `5,` are tuples, `()` is the empty tuple.
- `tuple(iterable)` converts (`tuple('ab')` → `('a', 'b')`); `tuple(5)` → `TypeError`.
- `+` and `*` build **new** tuples.
- A tuple may hold mutable objects: `t[1].append(4)` works when `t[1]` is a list. `t[1] += [4]` mutates the list **and then** raises `TypeError`.
- Unpacking needs the same number of names (`x, y = (1, 2, 3)` → `ValueError`); `first, *rest = t` puts the rest in a **list**.
- Parallel assignment evaluates the whole right side first: `a, b = b, a` swaps; `a, b = b, a + b` uses old values.
- `return x, y` returns one tuple; the caller may unpack it. Hashable tuples can be dict keys.

```python
a, b = 1, 2
a, b = b, a + b      # a = 2, b = 3
first, *rest = (1, 2, 3)
rest                 # [2, 3]   (a list!)
type((5)), type((5,))  # (<class 'int'>, <class 'tuple'>)
```

## Dictionaries {#dicts}

- Mapping key → value; `d[k]` reads (missing key → `KeyError`), `d[k] = v` creates or overwrites.
- `get(k)` returns `None` if missing, `get(k, default)` the default; `get` never inserts the key.
- `pop(k)` removes and returns the value (`KeyError` if absent unless a default is given); `del d[k]` removes; `update(other)` overwrites and adds.
- `in` and `for` work on the **keys**; use `d.values()` / `d.items()` for values or `(key, value)` tuples.
- Keys are unique: in `{'a': 1, 'a': 3}` the last value wins, the key keeps its first position.
- Keys must be **hashable** (immutable): str, numbers, tuples of hashables. A list, set, dict or a tuple containing a list → `TypeError: unhashable type`.
- Dicts keep **insertion order** (Python 3.7+); they are not sorted.
- Builders: `dict(a=1)`, `dict([('a', 1)])`, `dict(zip(keys, vals))`, `{k: v for ...}`.

```python
counts = {}
for ch in 'banana':
    counts[ch] = counts.get(ch, 0) + 1
counts              # {'b': 1, 'a': 3, 'n': 2}
'a' in counts       # True    (key test)
3 in counts         # False   (values are not tested)
d = {[1, 2]: 'x'}   # TypeError: unhashable type: 'list'
```

## Sets {#sets}

- Unordered collections of **unique**, hashable elements: duplicates are merged (`len({1, 1, 2})` is 2).
- `{}` is an empty **dict**; the empty set is `set()`.
- `set(iterable)` deduplicates: `set('aab')` has 2 elements; `sorted(set(l))` gives a sorted list without duplicates.
- Operators: `|` union, `&` intersection, `-` difference (not symmetric), `^` symmetric difference, `<=` subset, `<` strict subset. `+` is not defined (`TypeError`).
- `add(x)` (no effect if present), `remove(x)` (`KeyError` if absent), `discard(x)` (never raises), `pop()`.
- No indexing: `s[0]` → `TypeError`; no `append` / `insert`.
- Membership `x in s` is fast; equality ignores order.

```python
a, b = {1, 2, 3, 4}, {3, 4, 5}
a & b, a - b, a ^ b   # ({3, 4}, {1, 2}, {1, 2, 5})
len(a | b)            # 5
s = {10}
s.discard(99)         # nothing happens
s.remove(99)          # KeyError
```

## Comprehensions {#comprehensions}

- `[expr for x in it]` builds a **list** immediately; `{k: v for ...}` a dict; `{expr for ...}` a set.
- `(expr for x in it)` is a **generator expression** (not a tuple): lazy, consumed once; printing it shows `<generator object ...>`. Only this parenthesised form is a generator (despite the slide's wording).
- Filter: `[x for x in it if cond]` (no `else`). Transform: `[a if cond else b for x in it]` (the `else` is mandatory).
- Several `for` clauses nest like loops written in the same order: the first `for` is the outer loop.
- Wrong order (`[x for x in row for row in grid]`) → `NameError`.
- In a dict comprehension, repeated keys keep the **last** value.
- A comprehension can be nested inside another (e.g. a transpose `[[r[i] for r in m] for i in range(3)]`).

```python
[x if x > 2 else 0 for x in range(5)]       # [0, 0, 0, 3, 4]
[(i, j) for i in range(2) for j in range(2)] # [(0, 0), (0, 1), (1, 0), (1, 1)]
{x % 3: x for x in range(7)}                 # {0: 6, 1: 4, 2: 5}
g = (x * 10 for x in range(3))
sum(g), sum(g)                               # (30, 0)
```

## Type conversions {#conversions}

- `int(s)` needs an integer-looking string: `int('3.5')` and `int('abc')` → `ValueError`; surrounding spaces are ignored.
- `int(s, base)`: `int('ff', 16)` → 255, `int('101', 2)` → 5 (`'0x'` prefix allowed with base 16).
- `int(float)` **truncates toward zero**: `int(2.9)` → 2, `int(-2.9)` → -2.
- `list('abc')` → `['a', 'b', 'c']`; `tuple('ab')`, `set('aab')` also iterate; `list(5)` → `TypeError`; `list(d)` gives the keys.
- `str(container)` is its printed form: `str([1, 2])` is `'[1, 2]'` (6 characters).
- `ord('a')` → 97, `chr(99)` → `'c'`; uppercase letters start at 65.
- `bool(x)`: empty / zero values are False, anything else True — `bool('False')` and `bool([0])` are True.
- `'7' * 2` is `'77'` (repetition), not 14.

```python
int('ff', 16), int(-2.9)        # (255, -2)
''.join(chr(ord(c) + 1) for c in 'HAL')   # 'IBM'
str((1, 2)), list({'x': 1})     # ('(1, 2)', ['x'])
```

## `*args` and `**kwargs` {#args-kwargs}

- `*args` collects the extra **positional** arguments into a **tuple** (possibly empty).
- `**kwargs` collects the extra **keyword** arguments into a **dict** (in call order).
- Parameters after `*args` (or after a bare `*`) are **keyword-only**.
- At the call site, `f(*seq)` unpacks a sequence into positional arguments, `f(**d)` a dict into keyword arguments (keys must match parameter names).
- Passing a list without `*` gives one single argument: `count([1, 2, 3])` sees 1 argument.
- `zip(*matrix)` uses unpacking to transpose rows into columns.

```python
def foo(*args, **kwargs):
    return args, kwargs
foo(1, 2, x=3)          # ((1, 2), {'x': 3})
foo(*[1, 2])            # ((1, 2), {})

def f(a, *args, b=0):
    return a + sum(args) + b
f(1, 2, 3), f(1, 2, b=10)   # (6, 13)
```

## Standard library and pip {#stdlib-pip}

- Python ships with a large **standard library**: `os`, `sys`, `math`, `random`, `json`, `csv`, `re`, `time`, `datetime`, `itertools`, `collections`, `copy`, `pickle`, `tkinter`, `unittest`...
- Third-party packages (NumPy, Pandas, Matplotlib, requests, Flask, Pillow...) are installed with `pip install <name>` (sometimes `pip3`).
- **PyPI** (pypi.org) is the Python Package Index, where pip finds packages. (PyPy is something else: an interpreter.)
- List a project's dependencies, with versions, in `requirements.txt` (`numpy==1.17.3`) and install them all with `pip install -r requirements.txt`.
- `pip install requirements.txt` (without `-r`) looks for a package of that name; `import` never installs anything.
- The standard library is documented at docs.python.org/3/library; `sys.stdlib_module_names` (3.10+) lists its modules.

```python
import json, random            # standard library: always available
json.dumps({'a': 1})           # '{"a": 1}'
# import numpy                 # ModuleNotFoundError until: pip install numpy
```

```text
# requirements.txt
numpy==1.26.4
pandas==2.2.2
# shell: pip install -r requirements.txt
```

## Exam traps checklist {#traps}

- `append(list)` nests the list (len + 1); `extend` adds each element.
- `pop()` returns the removed element; `sort()`, `reverse()`, `append()` return `None`.
- `list.remove(missing)` → `ValueError`; `set.remove(missing)` and `d[missing]` → `KeyError`.
- `insert(i, x)` puts x **before** index i; a huge index appends.
- Slices exclude the stop index and never raise `IndexError`; single indexing does.
- Extended slice assignment with the wrong number of values → `ValueError`.
- `(5)` is an int; `(5,)` is a tuple; `tuple(5)` → `TypeError`.
- Tuples: item assignment → `TypeError`, `append` → `AttributeError`, but a list inside can change.
- `first, *rest = ...` gives `rest` as a list; unpacking count mismatch → `ValueError`.
- `in` on a dict tests keys; looping over a dict yields keys only.
- Duplicate dict keys: the last value wins; lists (and tuples containing lists) are unhashable.
- `{}` is a dict; use `set()` for an empty set; sets have no indexing and no `+`.
- `[... ]` comprehension = list, `( ... )` = generator (one pass only), `{k: v ...}` = dict, `{x ...}` = set.
- Filter `if` goes after the `for`; `if/else` goes before it.
- `int('3.5')` → `ValueError`; `int(-2.9)` → -2; `bool('False')` → True.
- Positional after keyword in a call, or non-default after default in a def → `SyntaxError`; missing / duplicate / unknown argument → `TypeError`.
- Default values are evaluated once, at `def` time.
- `*args` is a tuple, `**kwargs` a dict; `f(lst)` passes one argument, `f(*lst)` several.
