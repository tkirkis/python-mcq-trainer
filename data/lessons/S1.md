# S1 — Basics

## What Python is {#python-intro}

- Python is a **high-level, multi-paradigm** language: imperative/procedural, object-oriented and functional styles all work.
- It is **interpreted**: a program called the Python interpreter runs your code (CPython first compiles it to byte-code). Convenient, but slower than compiled languages.
- It is **garbage collected**: memory is freed automatically, there is no manual memory management.
- Typing is **dynamic and implicit**: you never declare a variable's type (see Variables).
- History: created by Guido van Rossum (first public release 1991), Python 2.0 in 2000, **Python 3.0 in 2008** (not backward compatible with Python 2: `print x` is a SyntaxError in Python 3).
- Ways to write/run code: the interactive prompt `>>>` (quick tests), a `.py` file run with `python file.py` (script) or `python -m file` (module), an IDE (IDLE, Spyder, PyCharm, VS Code), or a Jupyter notebook in the browser.
- **Jupyter notebooks** mix *code cells* (executable) and *Markdown cells* (text); the jupyter application is a local web server, the notebook is shown in the browser.
- **pip** ("Pip Installs Packages") installs third-party packages (numpy, pandas...) from **PyPI**. It is a **terminal command**, not Python code: typing `pip install numpy` at `>>>` is a SyntaxError.
- A programming language sits between human language and machine code; a compiler or an interpreter turns the program into machine instructions.

```python
# In a terminal (shell), NOT in Python:
#   pip install numpy
#   python hello.py        -> runs hello.py as a script
# At the Python prompt:
>>> pip install numpy      # SyntaxError
```

## Syntax basics {#syntax-basics}

- No braces: a **block** is introduced by a line ending with a **colon** `:` and consists of the following **indented** lines (4 spaces by convention).
- All lines of a block need the **same** indentation; an extra or missing indent is an `IndentationError` (a subclass of `SyntaxError`), raised before anything runs.
- A block cannot be empty: use `pass` (the do-nothing statement). A comment alone does not count as a statement.
- `#` starts a comment until the end of the line; a `"""docstring"""` as first statement documents a function/module (shown by `help(f)`, never printed when the function runs).
- Long statement over several lines: prefer **parentheses** (implicit continuation); a backslash `\` works only if it is the **last** character of the line.
- **Expression** = something that produces a value (possibly None) and can stand on the right of `=`: `3 * x`, `len(s)`, even `print("hi")` (value None).
- **Statement** = an instruction such as `if`, `for`, `while`, `def`, `import`, `pass`, an assignment: it cannot be assigned.
- A missing colon after `def`/`if`/`for`/`while` is a `SyntaxError`.
- Several simple statements can share a line with `;`, and a simple statement can follow the colon on the same line (`if x: print(x)`), but not another compound statement.

```python
total = (1 + 2 +
         3)            # OK: continuation inside parentheses
x = 5  # x = 10       -> comment, x is 5
def todo():
    pass               # required: the body cannot be empty
print(todo())          # None
```

## Elementary types {#types}

- Built-in elementary types: `NoneType` (single value `None`), `bool` (`True`/`False`), `int`, `float`, `complex`, `str`.
- `int` has **infinite precision**: `2 ** 100` is exact, ints never overflow.
- `float` is a 64-bit number: ~15–16 significant digits, max about 1.8e308. `2.0 ** 10000` raises `OverflowError`; `float(2**60 + 1) == float(2**60)`.
- Floats are binary approximations: `0.1 + 0.2 == 0.3` is **False** (`0.30000000000000004`). Compare with a tolerance.
- `complex(3, 4)` is `(3+4j)`; `abs()` gives the modulus `5.0`. The imaginary unit is written `j`.
- `type(x)` returns the class: `type(None)` is `<class 'NoneType'>`, `type(True)` is `bool` (not `int`, although bools behave as 0/1 in arithmetic).
- **Promotion**: int combined with float gives a float (`5 * 2.0 == 10.0`).
- Conversions: `int(3.99)` truncates towards zero → 3; `int("  42 ")` → 42; `int("3.5")` → **ValueError**; `float("1e3")` → 1000.0; `str(14.0)` → `'14.0'`.
- `round(x)` uses **banker's rounding**: halves go to the even integer (`round(2.5) == 2`, `round(3.5) == 4`).
- There is no separate char type: `'a'` is a `str` of length 1.

```python
print(type(1 / 2), type(7 // 2))   # <class 'float'> <class 'int'>
print(0.1 + 0.2)                   # 0.30000000000000004
print(2 ** 64 + 1)                 # 18446744073709551617
print(round(2.5), round(3.5))      # 2 4
print(int("3.5"))                  # ValueError
```

## Variables {#variables}

- An assignment `name = expression` evaluates the right side, then **binds** the name to the value. No declaration is needed.
- **Rebinding** (`a = a + 1`) makes the name refer to a new value; other names bound to the old value are not affected.
- **Dynamic typing**: the same name may refer to an int, then to a str (`x = 5; x = "5"`). Types belong to values, not to names.
- **Duck typing**: what matters is what an object can do, not its declared type (`x + x` works for ints, floats, strings).
- Multiple assignment `x, y = y, x + y` evaluates the **whole** right side first (swap: `a, b = b, a`). The counts must match, otherwise `ValueError`.
- Chained assignment `a = b = c = 0` binds the three names to the same value.
- Names: letters, digits, underscores, not starting with a digit; **case-sensitive** (`Total` ≠ `total`); keywords (`class`, `if`, `for`...) are forbidden; `first-name` is a subtraction.
- Using a name that was never assigned raises `NameError`.

```python
a = 3
b = a
a = a + 1
print(a, b)            # 4 3
x, y = 1, 2
x, y = y, x + y
print(x, y)            # 2 3
a, b = 1, 2, 3         # ValueError (too many values to unpack)
```

## Operators {#operators}

- `/` is **true division**: always a float (`10 / 5 == 2.0`).
- `//` is **floor division** (rounds down, towards −∞): `7 // 2 == 3`, `-7 // 2 == -4`; with a float operand the result is a float (`10.0 // 4 == 2.0`).
- `%` is the remainder, with the **sign of the divisor**: `-7 % 2 == 1`, `-1 % 3 == 2`, `7.5 % 2 == 1.5`. Always `a == (a // b) * b + a % b`.
- `divmod(a, b)` returns `(a // b, a % b)` (handy for HH:MM:SS); `pow(x, y)` is `x ** y`; `abs(-3.5) == 3.5`.
- `**` binds tighter than unary minus: `-2 ** 2 == -4`; it is **right-associative**: `2 ** 3 ** 2 == 2 ** 9 == 512`. Negative or float exponents give floats (`2 ** -1 == 0.5`, `9 ** 0.5 == 3.0`).
- Precedence: `**` > unary `-` > `* / // %` > `+ -` > comparisons > `not` > `and` > `or`.
- Augmented assignments: `x += 1`, `x *= 2`, `x //= 3`, `x %= 4`...
- `str * int` repeats (`"ab" * 3 == "ababab"`); `str + int`, `str * float`, `str * str` raise **TypeError**. `bool` acts as 0/1 (`True + True == 2`).

```python
print(7 / 2, 7 // 2, 7 % 2)     # 3.5 3 1
print(-7 // 2, -7 % 2)          # -4 1
print(2 + 3 * 4 ** 2 // 5)      # 11
print(divmod(3725, 60))         # (62, 5)
print("Age: " + 20)             # TypeError -> use str(20) or an f-string
```

## Comparisons and logic {#logic-comparisons}

- Comparisons `< <= > >= == !=` return a `bool`. Ordering an `int` against a `str` (`3 < "4"`) raises **TypeError**; `==` between them just gives False.
- Numbers compare by value across types: `1 == 1.0 == True`. `None == 0` is False.
- **Chained comparisons**: `a < b > c` means `a < b and b > c`. Trap: `5 > 3 == True` is `5 > 3 and 3 == True` → False.
- `==` compares **values**; `is` checks **identity** (same object). Two equal lists are `==` but not `is`. Use `is` for `x is None`.
- **Truthiness**: `0`, `0.0`, `''`, `[]`, `{}`, `None`, `False` are falsy; everything else is truthy — including `"0"`, `" "` and `"False"` (`bool("False")` is True).
- `x and y` returns x if x is falsy, else y; `x or y` returns x if x is truthy, else y: they return an **operand**, not necessarily a bool (`0 or "default"` → `'default'`). Only `not` always returns a bool.
- **Short-circuit**: the right operand is evaluated only if needed (`x != 0 and 10 / x > 1` is safe when x is 0).
- `not` has lower priority than comparisons (`not 1 == 2` is `not (1 == 2)`); `and` binds tighter than `or`.

```python
print(3 and 5, 0 and 5, [] or 0)    # 5 0 0
print(1 < 3 > 2, 5 > 3 == True)     # True False
print(True or False and False)      # True
a = [1, 2]; b = [1, 2]
print(a == b, a is b)               # True False
```

## Strings {#strings}

- Single, double or triple quotes all create a `str`; use the other quote kind or a backslash to include a quote (`"He said: \"hi!\""`).
- Escape sequences (`\n`, `\t`, `\\`) are **one** character: `len("a\tb\nc") == 5`.
- Indexing from 0; negative indices count from the end (`s[-1]` is the last character). An index out of range raises **IndexError**, but **slices** are clipped (`"code"[2:10] == "de"`).
- Slice `s[start:stop]`: start included, **stop excluded**; omitted bounds mean the beginning/end.
- Strings are **immutable**: `s[0] = "H"` raises TypeError. Methods return **new** strings: `s.upper()` alone does nothing to `s`.
- Methods: `upper/lower`, `strip` (both ends only), `split()` (any whitespace, drops empties) vs `split(" ")` (every single space, keeps empty strings), `sep.join(list_of_str)` (TypeError with ints), `replace(old, new[, count])`, `count`, `find` (−1 if absent) vs `index` (ValueError), `startswith/endswith` (case-sensitive).
- `+` concatenates, `str * int` repeats; `in` tests for a substring (case-sensitive).
- **f-strings**: `f"{x}/{y} = {x / y}"` evaluates the expressions in braces; without the `f` prefix the braces stay as text.
- Comparison is by Unicode code point: uppercase < lowercase (`"Zebra" < "apple"`), a prefix is smaller (`"ab" < "abc"`), `"10" < "9"`. `min`/`max` work on characters (space < digits < uppercase < lowercase).

```python
s = "DATASCIENCE"
print(s[4:7], s[-3:])          # SCI NCE
print("  a  b ".split())       # ['a', 'b']
print("  a  b ".split(" "))    # ['', '', 'a', '', 'b', '']
print("banana".replace("a", "o", 2), "hello".find("z"))   # bonona -1
name = "Ada"
print(f"Hi {name}!", "Hi {name}!")   # Hi Ada! Hi {name}!
```

## Conditionals {#conditionals}

- Control structures change the flow of execution (otherwise purely linear): `if/elif/else`, `while`, `for`, `try/except`. There is **no** `do...while` / `repeat...until`.
- `if/elif/else` tests the conditions **in order** and runs only the **first** true branch; later conditions are not even evaluated (so `d['missing']` in a later elif never raises).
- Put the most specific test first (leap year: test `% 400`, then `% 100`, then `% 4`).
- Two consecutive `if` statements are independent; only `elif` makes them exclusive. An `else` belongs to the `if` with the same indentation.
- `if x:` uses truthiness (`if items:` is False for an empty list).
- `if x = 5:` is a SyntaxError: comparison is `==`. The keyword is `elif` (not `else if`, `elseif`).
- Trap: `if x == 1 or 2:` is always true (`(x == 1) or 2`); write `x == 1 or x == 2` or `x in (1, 2)`.
- **Ternary** (conditional expression): `value_if_true if condition else value_if_false`; it can be chained. There is no `cond ? a : b`.
- A simple statement may follow the colon on the same line, but `else:` needs its own line.

```python
x = 15
if x > 10:
    print("A")
if x > 5:                 # separate if: tested too
    print("B")            # prints A then B
n = -3
print("pos" if n > 0 else "zero" if n == 0 else "neg")   # neg
```

## Loops {#loops}

- `while cond:` repeats as long as the condition is true — an **indefinite** number of times; the body must eventually make the condition false (beware `while n != 10` with `n += 2`).
- `for x in iterable:` runs a **definite** number of times over a range, a string (characters), a list... An `int` is not iterable (TypeError).
- `range(stop)`, `range(start, stop)`, `range(start, stop, step)`: start included, **stop excluded**; default step 1.
- Empty ranges: `range(5, 1)`, `range(0)`, `range(1, 5, -1)` — no error, zero iterations. Counting down needs a negative step: `range(10, 0, -3)` → 10, 7, 4, 1.
- Rebinding the loop variable inside a `for` body does not change the iteration; after the loop the variable keeps its **last** value (no new scope).
- Equivalent `while` for `for i in range(a, b)`: `i = a` / `while i < b:` / body / `i += 1` — where the increment goes matters (off-by-one).
- Nested loops multiply: inner `range(i)` runs 0, 1, 2... times.
- Accumulator patterns: `total += x`, `r = ch + r` (reverses a string), `a, b = b, a % b` (GCD).

```python
for i in range(2, 6):
    print(i, end=" ")        # 2 3 4 5
print(list(range(10, 0, -3)))  # [10, 7, 4, 1]
i = total = 0
while i < 5:
    i += 1
    total += i
print(total)                 # 15
```

## Loop control {#loop-control}

- `break` leaves the **innermost** loop immediately.
- `continue` skips the rest of the current iteration and goes to the next one (the loop goes on).
- In a `while` loop, `continue` placed **before** the counter update creates an infinite loop.
- A loop can have an `else` clause: it runs once when the loop ends **normally** (iterable exhausted / condition false), and is skipped only if a `break` is actually executed.
- The `else` also runs after zero iterations (e.g. `for d in range(2, 2)`), and `continue` does not affect it.
- Typical uses: search loops (`break` when found, `else` = "not found"), prime test, `while True:` + `break` to emulate do...until.
- `break`/`continue` outside a loop are a SyntaxError; `pass` does nothing at all.

```python
for n in [3, 7, 9]:
    if n % 3 != 0:
        print("found", n)
        break
else:
    print("none found")     # skipped: prints only "found 7"
for i in range(3):
    pass
else:
    print("done")           # done
```

## Imports and `__main__` {#imports-main}

- `import math` binds only the name `math`: use `math.sqrt(16)`; bare `sqrt` is a NameError.
- `from math import sqrt` binds only `sqrt` (the name `math` is **not** defined); `from math import *` binds all public names.
- `import math as m` binds the alias `m` only; `from mymodule import myf as mf` renames a function.
- You import to split your own code into files (`import mymodule` for `mymodule.py` in the same folder) or to use a library (standard library: math, random, os...; third-party via pip).
- `import` takes modules, not attributes: `import math.pi` fails.
- Importing a module **executes its top-level code** once.
- `__name__` is `'__main__'` in the file run directly, and the module name (e.g. `'mymod'`) in an imported file. Guard the main code with `if __name__ == "__main__":` so it does not run on import.

```python
import math as m
print(m.floor(3.7), m.ceil(3.2))   # 3 4
from math import sqrt
print(sqrt(16))                    # 4.0
print(math.pi)                     # NameError: math is not defined

if __name__ == "__main__":         # True only when run as a script
    print("main code")
```

## Functions basics {#functions-basics}

- `def name(params):` binds a name to a computation; don't forget the colon. The body runs only when the function is **called**.
- A script runs top to bottom: calling a function before its `def` has executed is a NameError.
- `return value` ends the function immediately (even inside a loop) and hands the value to the caller; code after it is dead.
- No `return` (or a branch that reaches the end) → the function returns **None**.
- `print` displays but returns None: `x = print("hi")` prints hi and sets x to None. Printing is not returning.
- Calling with the wrong number of arguments is a TypeError.
- Function names can be **rebound**: `g = f` keeps the old function even if `f` is redefined later. Built-in names too: `len = 5` makes `len("abc")` a TypeError.
- Useful built-ins: `len`, `type`, `id`, `print`, `int`, `float`, `bool`, `str`, `abs`, `round`, `min`, `max`.
- A **method** is a function attached to a type and called with a dot: `name.upper()`, `name.count("o")`.

```python
def sign(x):
    if x > 0:
        return "positive"
print(sign(0))          # None
def f():
    return 1
g = f
def f():
    return 2
print(f(), g())         # 2 1
```

## Exam traps checklist {#traps}

- `/` always returns a float; `//` floors (`-7 // 2 == -4`); `%` takes the divisor's sign (`-7 % 2 == 1`).
- `-2 ** 2 == -4` and `2 ** 3 ** 2 == 512`.
- `0.1 + 0.2 != 0.3`; `round(2.5) == 2` (banker's rounding).
- `"3" + 4` → TypeError, `"3" * 4` → `'3333'`, `int("3.5")` → ValueError.
- `bool("False")` is True; `0`, `''`, `[]`, `None` are falsy, `"0"` and `" "` are truthy.
- `and`/`or` return operands (`0 or "x"` → `'x'`), and short-circuit.
- `5 > 3 == True` is a chained comparison → False; `if x == 1 or 2:` is always true.
- `==` compares values, `is` identity: two equal lists are not `is`-identical.
- Strings are immutable: `s[0] = "x"` → TypeError; `s.upper()` does not change `s`.
- Slices exclude the stop and never raise; single indexes raise IndexError when out of range.
- `split()` vs `split(" ")`; `find` → −1 vs `index` → ValueError; `"-".join([1, 2])` → TypeError.
- An f-string needs the `f` prefix; `len("a\nb") == 3`.
- Only the first true branch of `if/elif` runs; later conditions are not evaluated.
- `range(a, b)` excludes b; `range(5, 1)` is empty (no error); counting down needs a negative step.
- Loop `else` runs unless `break` was executed (also after zero iterations).
- `continue` before the counter update in a `while` → infinite loop.
- A function without `return` returns None; `print` returns None.
- `import math` needs `math.`; `from math import sqrt` does not define `math`.
- Indentation errors and missing colons are detected before anything runs (no partial output).
