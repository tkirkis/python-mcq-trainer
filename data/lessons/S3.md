## Filesystem and paths {#filesystem-paths}

- Folders form a tree: the root is `/` on Linux/macOS, a drive such as `C:\` on Windows.
- An **absolute** path starts at the root (`/home/ann/a.txt`); a **relative** path (`data/a.txt`, `../a.txt`) is resolved from the **current working directory**.
- `.` is the current directory, `..` its parent.
- `os.getcwd()` returns the current working directory, which is *not* necessarily the folder of the script; `os.chdir(p)` changes it, and every relative path afterwards is resolved from the new place.
- `os.path.join` builds a path with the right separator (`/` on Linux/macOS); never glue paths with `+`.
- `os.path.basename` = last component, `os.path.dirname` = everything before it.
- `os.path.splitext` splits at the **last** dot and the extension **keeps its dot**: `('summary.final', '.txt')`.
- `os.path.exists(p)` answers `True`/`False`; it never raises for a missing path. `os.makedirs` creates nested folders.
- `glob.glob('folder/*.py')` returns a list of matching paths (prefixed like the pattern, in arbitrary order: use `sorted`). `*` does not enter subfolders.

```python
import os
p = os.path.join("reports", "q1", "summary.final.txt")  # 'reports/q1/summary.final.txt'
os.path.basename(p)                     # 'summary.final.txt'
os.path.splitext(os.path.basename(p))   # ('summary.final', '.txt')
os.path.basename(os.path.dirname(p))    # 'q1'
```

```python
import glob
sorted(glob.glob("class1/*.py"))   # ['class1/a.py', 'class1/b.py']  (not class1/sub/c.py)
```

## Shell and environment variables {#shell-env}

- Core shell commands: `ls` (list files), `pwd` (print working directory), `cd` (change directory), `mkdir`/`rmdir` (create/remove a folder), `rm` (remove a file), `cat` (show a file), `wc` (count lines/words), `grep` (search a pattern), `file` (file type).
- Every program runs inside an **environment**: a set of `NAME=value` string pairs (`env` or `set` lists them).
- `PATH` lists the folders where the OS looks for the programs you type (`:`-separated on Linux/macOS, `;` on Windows).
- In Python, `os.environ` behaves like a dict of **strings**.
- `os.environ["X"]` raises `KeyError` if `X` is not defined; `os.environ.get("X")` returns `None`, `os.environ.get("X", "dflt")` the default.
- Values must be `str`: `os.environ["N"] = 3` raises `TypeError`; reading always gives a str, so `os.environ["N"] * 2` repeats the string.
- Changes made through `os.environ` affect the current process (and programs it launches), not the parent shell.

```python
import os
os.environ["RETRIES"] = "3"
os.environ["RETRIES"] * 2              # '33'  (str repetition, use int() to compute)
os.environ.get("TIMEOUT", "10")        # '10'  (default, no error)
os.environ["TIMEOUT"]                  # KeyError
```

## Reading and writing files {#files-io}

- `open(name, mode)` returns a file object; the default mode is `'r'` (read, text). Close it with `f.close()` or, better, use `with open(...) as f:` which closes it automatically, even after an exception (`f.closed` is `True` after the block; the name `f` still exists).
- Modes: `'r'` read (file must exist, else `FileNotFoundError`); `'w'` write, **truncates** an existing file or creates it; `'a'` append at the end (creates if needed); `'x'` create, raises `FileExistsError` if the file exists; `'+'` adds the other direction (`'r+'` reads and writes without truncating, starting at position 0); `'b'` = binary.
- Writing to a file opened in `'r'` raises `io.UnsupportedOperation` (a subclass of `OSError`).
- `read()` returns everything as one str; `read(n)` the next n characters; `readline()` one line; `readlines()` a list of lines. Reading moves the position: a second `read()` returns `''`.
- Lines keep their `'\n'`: `print(line)` therefore shows an extra empty line; use `line.strip()` or `print(line, end='')`.
- A file object is iterable: `for line in f:` reads it line by line.
- `write(s)` adds **no** newline and returns the number of characters written; `writelines(list)` does not add newlines either.
- Binary mode (`'rb'`, `'wb'`) works with `bytes` (`b'hi\n'`); writing a `str` to a binary file raises `TypeError`. In UTF-8 a non-ASCII character such as `é` takes 2 bytes.
- `int(' 500\n')` works: `int()` ignores surrounding whitespace, handy when parsing lines.

```python
# notes.txt contains "first\nsecond\n"
with open("notes.txt") as f:
    print(f.readlines())        # ['first\n', 'second\n']
with open("notes.txt") as f:
    a = f.read()                # 'first\nsecond\n'
    b = f.read()                # ''  (already at the end)
```

```python
with open("log.txt", "w") as f:     # old content erased
    n = f.write("A")                # n == 1, no newline added
with open("log.txt", "a") as f:
    f.write("B\n")
open("log.txt").read()              # 'AB\n'
```

## Serialization: pickle and JSON {#serialization}

- Serializing = turning objects (lists, dicts...) into a sequence of bytes or text that can be stored on disk or sent, and rebuilt later.
- `pickle`: binary, Python-specific, keeps Python types exactly (tuples, sets, nested objects). The file **must** be opened in binary mode (`'wb'`, `'rb'`); with `'w'` you get `TypeError`.
- `json`: text, language-independent, very widespread, but only for dicts, lists, str, numbers, `True`/`False`/`None`.
- `dump(obj, file)` / `load(file)` work with files; `dumps(obj)` / `loads(text)` work with strings (the **s** means string). `json.dumps` returns a `str`, `pickle.dumps` returns `bytes`, `json.dump` returns `None`.
- JSON text uses double quotes, `true`, `false`, `null`; a single-quoted text is invalid and `json.loads` raises `json.JSONDecodeError` (a `ValueError`).
- JSON round-trip changes types: tuples come back as **lists**, and dict keys always become **strings** (`{1: 'a'}` gives `{'1': 'a'}`).
- Sets, bytes and arbitrary objects are not JSON serializable: `json.dumps({1, 2})` raises `TypeError`.

```python
import json
s = json.dumps({"k": (1, 2), 3: None})   # '{"k": [1, 2], "3": null}'  (a str)
json.loads(s)                           # {'k': [1, 2], '3': None}
json.dumps({1, 2})                      # TypeError: not JSON serializable
```

```python
import pickle
with open("acc.pkl", "wb") as f:        # binary is mandatory
    pickle.dump({"hist": [("dep", 50)], "ids": {1, 2}}, f)
with open("acc.pkl", "rb") as f:
    pickle.load(f)                      # same dict, tuple and set preserved
```

## Modules and packages {#modules-packages}

- A module is a `.py` file; a package is a folder of modules marked by an `__init__.py` file (executed when the package is imported).
- `import m` runs `m.py` **once** (the module is then cached): importing it again does not re-run its code.
- `import m` binds only the name `m` (use `m.f()`); `from m import f` binds `f` directly; `import m as x` binds only `x` (the name `m` is undefined).
- `from m import *` imports the public names, skipping those that start with `_`.
- `from m import v` copies the current binding: if the module later rebinds `m.v`, your `v` does not change.
- `__name__` is `'__main__'` in the script that is run, and the module name when the file is imported, hence the idiom `if __name__ == '__main__': main()`.
- Importing a missing module raises `ModuleNotFoundError` (a subclass of `ImportError`).
- Typical project layout: a top-level script (`app.py` / `main.py`), packages with `__init__.py`, a `tests` folder, `README.md`, code following PEP 8.

```python
# tools.py:  print("tools:", __name__)
import tools              # prints  tools: tools
import tools              # prints nothing (already imported)
print(__name__)           # __main__
```

```python
import math as m
m.sqrt(16)      # 4.0
math.sqrt(16)   # NameError: name 'math' is not defined
```

## Exceptions {#exceptions}

- A **syntax error** is detected before the program starts (nothing runs); an **exception** happens at run time, when the faulty line is reached.
- An uncaught exception stops the program: the lines after it never run.
- `try` / `except` / `else` / `finally`: `except` runs if the try block raised a matching exception; `else` only if the try block raised **nothing**; `finally` **always** runs (after `return`, `break`, `continue`, handled or unhandled exceptions).
- An `except` clause also catches **subclasses**; clauses are tested from top to bottom and the **first** match wins, so put specific classes before general ones (`except Exception` first catches everything).
- Hierarchy to know: `ZeroDivisionError` < `ArithmeticError`; `KeyError`, `IndexError` < `LookupError`; `FileNotFoundError`, `FileExistsError` < `OSError` (`IOError` is the same as `OSError`); `ModuleNotFoundError` < `ImportError`; all < `Exception`. `ValueError` and `TypeError` are unrelated.
- Common ones: `int('x')` → `ValueError`; `'a' + 1` → `TypeError`; missing key → `KeyError`; bad index → `IndexError`; undefined name → `NameError`; failed `assert` → `AssertionError`.
- `except (ValueError, TypeError) as e:` catches several classes; `str(e)` / `print(e)` gives the message, `type(e).__name__` the class name. The name `e` is deleted when the handler ends.
- `raise ValueError("msg")` raises; a bare `raise` inside `except` re-raises the current exception.
- An exception raised inside `except`, `else` or `finally` is **not** caught by the clauses of the same `try`.
- Custom exceptions: `class BankError(Exception): pass`, then `raise BankError("...")`.
- A `return` in `finally` overrides the `try`'s return value; rebinding a variable in `finally` does not.

```python
def f(x):
    try:
        r = 10 / x
    except ZeroDivisionError:
        print("except")
    else:
        print("else")
    finally:
        print("finally")
f(0)   # except, finally
f(5)   # else, finally
```

```python
try:
    {"a": 1}["b"]
except LookupError:     # matches KeyError (subclass): this one runs
    print("lookup")
except KeyError:        # never reached
    print("key")
```

## Time and dates {#time-dates}

- `time.time()` returns a float timestamp: seconds since 1 January 1970. The difference of two timestamps measures elapsed time.
- `time.sleep(s)` pauses the program for `s` seconds and returns `None`.
- `datetime.datetime.now()` gives the current date and time as an object with `.year`, `.month`, `.day`, `.hour`, `.minute`...
- `datetime(2024, 3, 1) - timedelta(days=1)` uses the real calendar (2024 is a leap year: 29 February).
- Subtracting two dates gives a `timedelta` (`.days`).
- `weekday()`: Monday = 0 ... Sunday = 6 (`isoweekday()`: Monday = 1 ... Sunday = 7).
- `strftime("%d/%m/%Y %H:%M")` formats with zero-padded fields.

```python
from datetime import date, datetime, timedelta
datetime(2024, 3, 1) - timedelta(days=1)        # 2024-02-29 00:00:00
(date(2024, 2, 15) - date(2024, 1, 15)).days    # 31
datetime(2024, 7, 14, 9, 5).strftime("%d/%m/%Y %H:%M")   # '14/07/2024 09:05'
datetime(2024, 7, 14).weekday()                 # 6 (Sunday)
```

## Exam traps checklist {#traps}

- `open()` without a mode is `'r'`: read-only text; `f.write()` then raises `io.UnsupportedOperation`.
- `'w'` empties an existing file immediately; `'a'` appends; `'x'` fails with `FileExistsError` if the file exists.
- Reading a missing file (`'r'`, `'r+'`, `'rb'`) raises `FileNotFoundError`; `'w'` and `'a'` create it.
- Lines read from a file keep their `'\n'`: `print(line)` doubles the newlines.
- A second `f.read()` returns `''`: the position is at the end.
- `write()` adds no newline and returns the number of characters written.
- Binary mode returns/accepts `bytes`; mixing `str` and `bytes` gives `TypeError`.
- pickle needs `'wb'`/`'rb'`; JSON files are text (`'w'`/`'r'`).
- JSON: tuples come back as lists, int keys come back as strings, sets are not serializable.
- `dumps`/`loads` = strings, `dump`/`load` = files; `json.dump` returns `None`.
- `finally` always runs, even after `return`; a `return` inside `finally` wins.
- `else` runs only when the `try` block raised nothing; exceptions raised in `else`/`except` are not caught by the same `try`.
- The first matching `except` wins and catches subclasses too: `except Exception` placed first hides everything below.
- `ValueError` is not a `TypeError`: `int('x')` is a `ValueError`, `'a' + 1` a `TypeError`.
- After an uncaught exception, nothing else runs (later prints never appear).
- A module's code runs only on its first import; `__name__ == '__main__'` only in the script that is run.
- `import m as x` does not define `m`; `from m import *` skips names starting with `_`.
- `os.getcwd()` is the working directory, not the script's folder; relative paths follow `os.chdir`.
- `os.environ` values are strings; `os.environ['MISSING']` raises `KeyError`, `.get()` returns `None`.
- `splitext` keeps the dot and splits at the last dot; `weekday()` counts Monday = 0.
