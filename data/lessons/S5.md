## Classes and objects {#classes-objects}

- A `class` is a blueprint; calling it (`Dog('Rex')`) builds a new **instance**. `Dog` without parentheses is just the class itself.
- `__init__(self, ...)` *initialises* the new object; `self` is filled in automatically, so you pass every other parameter. A missing one raises **TypeError**.
- `__init__` must return None: `return 5` inside it raises **TypeError** when the class is called.
- Attributes are stored with `self.name = value`. A bare `name = value` inside a method only creates a local variable.
- Attributes can be added to one object at any time (`d1.age = 7`); the other instances do not get them → **AttributeError**.
- A missing attribute never defaults to None: it raises AttributeError.
- Every call creates a distinct object: `Tag('x') is Tag('x')` is False. `b = a` does not copy, it gives a second name to the same object.
- The class body runs once, at definition time (a `print` in it runs immediately); `__init__` runs on each instantiation.
- Misspelled `_init_` / `__int__` is never called: the default initializer takes no arguments → `Fruit('kiwi')` raises TypeError.
- Mutable default in `__init__(self, items=[])`: the list is shared by all instances. Use `items=None`.

```python
class Book:
    def __init__(self, title):
        self.title = title

b1, b2 = Book('Dune'), Book('Emma')
b1.pages = 412
print(b1.pages)   # 412
print(b2.pages)   # AttributeError: only b1 got a 'pages' attribute
```

```python
class Lamp:
    def __init__(self):
        self.on = False

l = Lamp          # no parentheses: l is the class, not an instance
# l.on            -> AttributeError
print(Lamp().on)  # False
```

## Methods {#methods}

- A method is a function defined in a class; its first parameter receives the instance (named `self` by convention only, `this` would work too).
- `obj.f(x)` is shorthand for `Class.f(obj, x)` (message passing). `Class.f(x)` alone passes x as self.
- Forgetting `self` in the `def`: `obj.f()` raises **TypeError** (takes 0 positional arguments but 1 was given). Called on the class (`Class.f()`), such a function works.
- Inside a method, other members need the prefix: `self.other()`, `self.value`. A bare `other()` → **NameError**.
- A method without `return` returns None (side effects on `self` still happen). Chaining `obj.a().b()` needs `return self`.
- An instance attribute with the same name as a method hides the method: `self.score = 0` then `p.score()` → TypeError ('int' object is not callable).
- `obj.method` without parentheses is a *bound method*: it remembers obj and can be stored and called later (this is how GUI callbacks work).
- Methods mutate the object in place: every alias of the object sees the change.

```python
class Calc:
    def __init__(self, base):
        self.base = base
    def add(self, x):
        return self.base + x

c = Calc(10)
print(c.add(5), Calc.add(c, 5))   # 15 15
f = c.add                         # bound method
print(f(1))                       # 11
# Calc.add(5)                     -> TypeError (x missing)
```

## Special methods {#special-methods}

- Special ("dunder") methods are called by Python syntax: `print`/`str()` → `__str__`, `repr()`/containers/REPL → `__repr__`, `obj[i]` → `__getitem__`, `obj[i] = v` → `__setitem__`, `len()` → `__len__`, `obj()` → `__call__`, `+` → `__add__`, `==` → `__eq__`, `for` → `__iter__`.
- Only the exact names count: `__length__` or `__plus__` mean nothing to Python.
- `print([obj])` shows the elements with `__repr__`, not `__str__`. Without `__str__`, print falls back to `__repr__`; with neither you get `<__main__.C object at 0x...>`.
- `__str__` must **return** a str: returning None (e.g. printing inside it) → TypeError.
- Default `==` is identity: two objects with equal attributes are not equal until you define `__eq__`. `in` on a list uses `==`; `is` can never be overridden.
- No `__len__` → `len(obj)` raises TypeError. With `__len__` (and no `__bool__`), an empty object is falsy.
- Only `__getitem__` defined: reading works (even slices are forwarded), assignment raises TypeError.
- `sum(objs)` starts with `0 + obj` → TypeError unless the class has `__radd__` or you pass a start value.
- An `__iter__` written with `yield` returns a new generator on each call, so the object can be looped over many times.

```python
class Temp:
    def __str__(self):
        return 'str'
    def __repr__(self):
        return 'repr'

t = Temp()
print(t, [t])          # str [repr]

class Multiplier:
    def __init__(self, k):
        self.k = k
    def __call__(self, x):
        return self.k * x

print(Multiplier(2)(21))   # 42
```

```python
class Coin:
    def __init__(self, v):
        self.v = v
    def __eq__(self, other):
        return self.v == other.v

print(Coin(2) == Coin(2), Coin(2) is Coin(2))   # True False
```

## Inheritance {#inheritance}

- `class Child(Parent):` — members not redefined in Child are looked up in Parent (then its parents, up to `object`).
- Overriding: the child's version is found first; the parent's version runs only if the child calls `super().method()` (or `Parent.method(self)`).
- A child with no `__init__` inherits the parent's, including its required arguments.
- A child `__init__` that does not call `super().__init__(...)` leaves the parent's attributes uncreated → **AttributeError** later. Methods are still inherited.
- `super().__init__(name)` — never pass `self` again (`super().__init__(self, name)` → TypeError).
- Order of prints follows where `super()` is called: code before it runs first.
- Inside an inherited method, `self` is the real object: `self.title()` picks the child's override (polymorphism).
- Multiple inheritance `class D(B, C)`: lookup follows the MRO (D, B, C, ..., object), left to right; in a diamond each class appears once and `super()` goes to the *next class in the MRO*, not simply the parent.
- `isinstance(obj, C)` is True for C and every parent of the object's class; `type(obj) == Parent` is False. Inheritance never goes downward or sideways.
- Every class inherits from `object`; `bool` is a subclass of `int`, so `isinstance(True, int)` is True.

```python
class A:
    def go(self): print('A')
class B(A):
    def go(self): print('B'); super().go()
class C(A):
    def go(self): print('C'); super().go()
class D(B, C):
    pass

D().go()   # B, C, A (one per line): MRO is D, B, C, A, object
```

```python
class Account:
    def __init__(self, owner):
        self.owner = owner

class Savings(Account):
    def __init__(self, owner, rate):
        super().__init__(owner)   # without this line: s.owner -> AttributeError
        self.rate = rate

s = Savings('Ana', 0.02)
print(s.owner, isinstance(s, Account))   # Ana True
```

## Class vs instance attributes {#class-instance-attributes}

- A variable assigned in the class body is a **class attribute**, shared by all instances; `self.x = ...` creates an **instance attribute**.
- Lookup order: instance → class → parent classes. Instances read the class value at access time, so `Dog.legs = 3` is seen by every instance without its own `legs`.
- Assigning through an instance (`d1.legs = 3`) creates an instance attribute that *shadows* the class one; the class and the other instances are unchanged.
- `self.count += 1` on an int class attribute reads the class value but writes an instance attribute: the class counter stays unchanged. Use `ClassName.count += 1`.
- Mutable class attribute (`tricks = []`) + `self.tricks.append(x)` mutates the single shared list → every instance sees it. Create the list in `__init__` instead.
- `self.items = self.items + [x]` builds a new list and stores it on the instance (no sharing); `append` and `+=` mutate the shared list.
- The class cannot see instance attributes: `Car.color` → AttributeError.
- A bare class-attribute name inside a method (`pi * r`) → NameError: write `self.pi` or `Circle.pi`.

```python
class Dog:
    legs = 4
    tricks = []

a, b = Dog(), Dog()
a.legs = 3              # instance attribute on a only
a.tricks.append('sit')  # mutates the shared class list
print(a.legs, b.legs, Dog.legs)   # 3 4 4
print(b.tricks)                   # ['sit']
```

```python
class Counter:
    count = 0
    def inc(self):
        self.count += 1   # creates/updates an instance attribute

c = Counter(); c.inc(); c.inc()
print(Counter.count, c.count)     # 0 2
```

## OOP concepts {#oop-concepts}

- OOP splits a program into objects that interact; it helps architecture, team work and unit testing.
- Blueprint analogy: class = blueprint, objects = houses built from it, one given house = an instance.
- **Abstraction**: expose only the essential features, hide irrelevant details.
- **Encapsulation**: bundle data and the functions working on it into one unit, the class.
- **Inheritance**: a subclass acquires the members of another class.
- **Polymorphism**: the same call (`a.speak()`) gives class-specific behaviour; overriding methods is polymorphism. In Python any object with the right method works (duck typing), no common parent needed.
- Built-in types are classes: `type([])` is `list`, `dir(list)` lists its methods, `(12).bit_length()` is 4; even classes are objects (`type(list)` is `type`).
- Privacy is a convention: `_x` means "internal" but is accessible; `__x` is name-mangled to `_ClassName__x`, so `obj.__x` from outside → AttributeError.

```python
n = 12
print(type(n).__name__, n.bit_length())   # int 4

class Safe:
    def __init__(self):
        self._code = 1234
        self.__key = 'abc'

s = Safe()
print(s._code, s._Safe__key)   # 1234 abc
# s.__key                      -> AttributeError
```

## GUI, MVC and callbacks {#gui-mvc}

- **3-tier architecture**: presentation tier (user interface), logic tier (commands, decisions, calculations), data tier (database / file storage). Benefits: independent layers, scalability, reliability.
- **MVC**: Model = data + its logic; View = presents data and handles user interaction; Controller = interface between Model and View (the view alerts the controller, which updates the model; the model notifies the view).
- GUI toolkits for Python: Tkinter (Tk), PyQt, Pyglet, Pygame...
- Tk widgets: frame, button, checkbutton, radiobutton, label, entry (single-line input), text (multi-line), listbox, scale, scrollbar, canvas (drawing).
- A callback is passed, not called: `command=save` (correct) vs `command=save()` (runs immediately at creation and passes None).
- Callbacks with arguments: `command=lambda: save_as(name)`, a closure returned by a factory function, or a callable object (instance of a class with `__call__`).
- Lambdas created in a loop capture the *variable*, not its value: all see the last value. Fix with `lambda i=i: ...`.

```python
def say_hi():
    print('hi')

cmd = say_hi()   # prints hi NOW; cmd is None
cmd = say_hi     # correct: the function itself, called later

callbacks = [lambda: print(i) for i in range(3)]
for cb in callbacks:
    cb()                       # 2 2 2 (one per line)
fixed = [lambda i=i: print(i) for i in range(3)]
fixed[0]()                     # 0
```

## Advanced *args and **kwargs {#args-kwargs-advanced}

- `*args` collects the extra positional arguments into a **tuple**; `**kwargs` collects the extra keyword arguments into a **dict**.
- Positional arguments fill the named parameters first, then go into `*args`.
- Parameters written after `*args` are **keyword-only**: `total(1, 2, 10)` puts 10 in args, never in `start`; without a default they are required → TypeError if missing.
- Call-site unpacking: `f(*lst)` spreads a list into positional arguments, `f(**d)` spreads a dict into keyword arguments. `f(lst)` passes one argument: `args == (lst,)`.
- Giving a parameter twice (`f(1, a=3)` for `def f(a, ...)`) → TypeError (multiple values).
- `**kwargs` only receives keywords that match no named parameter.
- Defining `def sum(*args, ...)` shadows the built-in `sum`: `sum([1, 2, 3])` then means `0 + [1, 2, 3]` → TypeError.

```python
def total(*args, verbose=False, start=0):
    s = start
    for a in args:
        s += a
    return s

print(total(1, 2, 3, 10))        # 16  (10 goes into args)
print(total(1, 2, 3, start=10))  # 16
print(total(*[1, 2, 3]))         # 6

def foo(*args, **kwargs):
    print(args, kwargs)

foo(['one', 'two'], x=1)         # (['one', 'two'],) {'x': 1}
```

## Exam traps checklist {#traps}

- `def m():` in a class, then `obj.m()` → TypeError (self is always passed).
- `print(d)` instead of `print(self.d)` in a method → NameError.
- `balance = balance` in `__init__` creates no attribute → AttributeError later.
- Attribute added to one instance only → AttributeError on the other instances.
- `__init__` returning a value → TypeError; `_init_` typo → TypeError on `C(arg)`.
- `l = Lamp` (no parentheses) is the class, not an instance.
- `print(obj)` uses `__str__`, `print([obj])` uses `__repr__`; `__str__` must return a str.
- `==` between objects is identity until `__eq__` is defined; `is` is always identity.
- `len(obj)` without `__len__` → TypeError; `sorted(objs)` without `__lt__` or `key=` → TypeError.
- Child `__init__` without `super().__init__()` → parent attributes missing → AttributeError.
- `super().__init__(self, x)` passes self twice → TypeError.
- Overridden method: only the child's version runs unless it calls `super()`.
- `class D(B, C)`: B is searched before C; `super()` follows D's MRO.
- `isinstance(child_obj, Parent)` True, `type(child_obj) == Parent` False; `isinstance(True, int)` True.
- Class attribute changed through an instance → new instance attribute; the class keeps its value.
- `tricks = []` as class attribute + `append` → shared by all instances.
- `self.count += 1` on a class counter does not update the class.
- `command=f()` calls f immediately; loop lambdas see the last value of the loop variable.
- Parameters after `*args` are keyword-only; `f(lst)` vs `f(*lst)`.
- `obj.__x` from outside → AttributeError (name mangling); `obj._x` works.
