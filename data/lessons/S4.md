# S4 — Under the hood: scopes, aliasing, mutability

## How the interpreter runs a script {#interpreter-execution}

- Hardware in one line each: the **CPU** computes, **RAM** is fast short-term memory (running programs and their objects live there), the **disk** stores files permanently (slow, non-volatile).
- A `.py` file is just text; the `python` program (the interpreter) reads it and executes it. Ways to start it: `python3 file.py`, `python3 -m module`, `python3 -c "code as a string"`.
- A script runs **top to bottom, one statement at a time**. Nothing is hoisted.
- `import math` loads the module and binds the name `math`; its contents are then reached as `math.sqrt`, `math.pi`...
- `def` **does not run the body**: it creates a function object and binds it to the name. The body runs only when the function is called.
- Calling a function on a line *before* its `def` has executed → `NameError`.
- Names inside a function body are looked up **when the function runs**, so a function may use a helper defined later in the file, as long as the helper's `def` has run before the call.
- A second `def` with the same name simply rebinds the name to a new function.

```python
print('start')
def f():
    print('inside')     # not executed: f is never called
print('end')            # output: start / end

print(g(2))             # NameError: g does not exist yet
def g(x):
    return x * 2
```

```python
def main():
    return helper() * 2  # helper looked up at call time
def helper():
    return 1
print(main())            # 2
```

## Scopes: local, enclosing, global, built-in {#scopes}

- A function call creates a new **local scope**. Names are resolved in LEGB order: Local, Enclosing function, Global (module), Built-in.
- **Reading** a global inside a function needs no declaration (the value is read at call time, not at `def` time).
- **Assigning** a name anywhere in a function makes it local in the *whole* function body (decided at compile time). Reading it before the assignment → `UnboundLocalError` (e.g. `count += 1` on a global without `global count`).
- `global x` makes assignments rebind the module-level `x`; it can even create a new global. It is not inherited by nested functions.
- `nonlocal x` rebinds `x` in the nearest **enclosing function**; it never reaches module level. `nonlocal` with no enclosing function variable (e.g. the enclosing function declared it `global`) → `SyntaxError` before anything runs.
- A parameter is a local variable: rebinding it does not affect the caller's variable, and it shadows a global of the same name.
- **No block scope**: names created in `if`/`for`/`while` blocks (including the loop variable) still exist after the block, with their last value.
- A local variable named like a built-in (`len = 0`) hides the built-in only inside that function.

```python
x = 'g'
def outer():
    x = 'o'
    def inner():
        nonlocal x
        x = 'i'
    inner()
    print(x)        # i   (outer's x was rebound)
outer()
print(x)            # g   (global untouched)
```

```python
value = 1
def show(flag):
    if flag:
        value = 2   # makes `value` local everywhere in show
    print(value)
show(True)          # 2
show(False)         # UnboundLocalError (no fallback to the global)
```

```python
for i in range(3):
    square = i * i
print(i, square)    # 2 4  (no block scope: both names survive the loop)
```

## Identity vs equality {#identity-equality}

- Every object has an identity, returned by `id()`; `a is b` means "same object" (same id).
- `a == b` compares **values**. Two separately created lists with the same content: `==` is True, `is` is False.
- For your own classes, `==` falls back to identity unless the class defines `__eq__`; `__eq__` never changes the result of `is`.
- `in` on a list compares elements with `==`.
- `None` is a single object: test it with `x is None` (not `not x`, which is also True for `0`, `''`, `[]`).
- A function without `return` returns `None`; in-place methods such as `append`/`sort` return `None` too.
- `+=` on a list keeps the same object (same id); `a = a + [x]` creates a new one.
- Dicts are equal if they hold the same pairs, whatever the insertion order (but `list(d1)` keeps that order).
- Do not reason about `is` on small ints or short strings: their sharing is an implementation detail. Use `is` for `None` and for "same object" questions.

```python
a = [1, 2]
b = [1, 2]
print(a == b, a is b)          # True False
print([].append(1) is None)    # True

class P:
    def __init__(self, x):
        self.x = x
print(P(1) == P(1))            # False (no __eq__: identity)
```

## Aliasing {#aliasing}

- Assignment never copies: `b = a` binds a second name to the **same object**.
- A **mutation** (append, item assignment, `+=` on a list, `sort()`, `clear()`...) is visible through every alias.
- A **rebinding** (`a = something_else`) only moves that one name; other aliases keep the old object.
- Arguments are passed by object reference: a function that mutates its parameter changes the caller's object; a function that rebinds its parameter does not.
- Containers store references: `[a, a, a]` holds three references to one list, `dict.fromkeys(keys, [])` shares one list between all keys.
- A `for` loop variable is a name for the current element: `n = n * 10` does not change the list, but `row.append(0)` mutates the inner list it refers to.
- A function that returns the list it received returns the same object, not a copy.

```python
def f(a, b):
    a = a + [0]     # rebinding: caller's list untouched
    b.append(0)     # mutation: caller sees it
x, y = [1], [1]
f(x, y)
print(x, y)         # [1] [1, 0]
```

```python
a = [1, 2]
l = [a, a]
a[0] = 9
print(l)            # [[9, 2], [9, 2]]
```

## Mutable vs immutable {#mutability}

- Mutable: `list`, `dict`, `set` (and most user objects). Immutable: `int`, `float`, `bool`, `str`, `tuple`, `None`.
- Immutable objects cannot change: "modifying" them creates a new object and rebinds the name (`x += 1`, `s += 'd'`, `t += (3,)`); aliases keep the old value.
- String methods (`upper`, `strip`, `replace`) **return a new string**; calling them without storing the result changes nothing. `s[0] = 'P'` → `TypeError`.
- On a list, `a += [x]` / `a *= 2` / `extend` / slice assignment mutate **in place**; `a = a + [x]` / `a = a * 2` build a new list.
- A tuple can contain a mutable list: `t[0].append(1)` works, `t[0] = ...` raises `TypeError`, and `t[0] += [1]` raises `TypeError` **after** extending the list.
- **Mutable default arguments** are created once, when `def` runs, and shared by all calls: `def f(x, acc=[])` accumulates. Use `acc=None` then `if acc is None: acc = []`.
- Do not add/remove items of a list while looping over it (items get skipped); a dict or set that changes size during iteration raises `RuntimeError`.

```python
def add(x, acc=[]):
    acc.append(x)
    return acc
add(1)
print(add(2))       # [1, 2]  (same default list)

t = ([1], 2)
try:
    t[0] += [3]
except TypeError:
    print(t)        # ([1, 3], 2)  mutated, then the store failed
```

```python
nums = [2, 4, 5, 6]
for n in nums:
    if n % 2 == 0:
        nums.remove(n)
print(nums)         # [4, 5]  (4 was skipped)
```

## Copying: shallow vs deep {#copying}

- Shallow copies of a list: `a[:]`, `list(a)`, `a.copy()`, `copy.copy(a)`; of a dict: `dict(d)`, `d.copy()`, `copy.copy(d)`. They create a **new outer container** filled with references to the **same items**.
- With nested data, the inner lists are still shared after a shallow copy: mutating `b[0]` shows in `a`, but replacing `b[0] = ...` does not.
- `copy.deepcopy(x)` copies recursively: nothing mutable is shared with the original (copies are expensive).
- A copy is `==` to the original but not `is`.
- `[[0] * 3] * 3` repeats a reference to **one** row: changing one cell changes every row. Use `[[0] * 3 for _ in range(3)]`.
- `[0] * 3` is safe: ints are immutable, so sharing them does not matter.
- `a[:]` on the **right** of `=` copies; on the **left** (`a[:] = [0]`) it replaces the contents of the same list in place.

```python
import copy
a = [[1, 2], [3]]
b = a.copy()           # shallow
b[0].append(9)
b[1] = [0]
print(a)               # [[1, 2, 9], [3]]

c = copy.deepcopy(a)
c[0].append(7)
print(a[0])            # [1, 2, 9]  (unchanged)
```

```python
g = [[0] * 2] * 2
g[0][0] = 5
print(g)               # [[5, 0], [5, 0]]
```

## Functions are first-class objects {#first-class-functions}

- A function is an object: it can be bound to another name, stored in a list or dict, passed as an argument, returned from another function.
- Pass the function itself (`run(f, 4)`), not the result of a call (`run(f(3), 4)` passes a number → `TypeError: 'int' object is not callable`).
- `del f` removes the name only; other names bound to the function still work.
- A nested function that uses variables of its enclosing function is a **closure**: it keeps them alive after the outer function returns.
- Rebinding a captured variable needs `nonlocal`; mutating a captured list (`box[0] += 1`) does not.
- Each call of the outer function creates fresh variables, so two closures built by two calls are independent.
- **Late binding**: closures see the variable, not its value at creation time: `[lambda: i for i in range(3)]` all return 2. Capture the value with a default: `lambda i=i: i`.

```python
def counter():
    n = 0
    def step():
        nonlocal n
        n += 1
        return n
    return step
a, b = counter(), counter()
a(); a()
print(a(), b())        # 3 1
```

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])   # [2, 2, 2]
gs = [lambda i=i: i for i in range(3)]
print([g() for g in gs])   # [0, 1, 2]
```

## Recursion and the call stack {#recursion}

- A recursive function calls itself; it needs a **base case** that is actually reached (`n == 0` is never reached from an odd `n` decreasing by 2).
- Each call gets its own frame with its own local variables, pushed on the **call stack** (LIFO: the last call made is the first to finish).
- Without a reachable base case, Python raises `RecursionError` when the depth limit (about 1000 calls by default) is exceeded; it does not run forever.
- Code **before** the recursive call runs on the way down; code **after** it runs on the way back up, in reverse order.
- The value of a recursive call must be returned (`return f(n - 1)`); otherwise the outer calls return `None`.
- Functions can call each other (mutual recursion), e.g. `f` → `g` → `f`; they only need to be defined before the first call.

```python
def walk(n):
    if n == 0:
        print('*', end='')
        return
    print(n, end='')
    walk(n - 1)
    print(n, end='')
walk(2)                # 21*12
print()

def fact(n):
    if n == 0:
        return 1
    return n * fact(n - 1)
print(fact(4))         # 24
# fact(-1) -> RecursionError (the base case is never reached)
```

## Keywords vs built-in names {#keywords}

- **Keywords** are reserved words of the grammar: `False None True and as assert break class continue def del elif else except finally for from global if import in is lambda nonlocal not or pass raise return try while with yield` (plus `async`, `await`). Assigning to them is a `SyntaxError`.
- **Built-in names** (`print`, `len`, `list`, `dict`, `str`, `int`, `sum`, `range`, `sorted`...) are ordinary names in the built-in scope: they *can* be rebound.
- Rebinding a built-in hides it in that scope: after `list = [1, 2]`, `list('abc')` raises `TypeError: 'list' object is not callable`. A local `len = 0` only hides `len` inside that function.
- Avoid naming variables `list`, `dict`, `str`, `sum`, `max`, `id`, `type`...
- `import keyword` then `keyword.iskeyword('for')` → `True`, `keyword.iskeyword('print')` → `False` (`print` is a function in Python 3, not a keyword).

```python
sum = 10            # legal, but hides the built-in sum
# sum([1, 2])       -> TypeError: 'int' object is not callable
# None = 0          -> SyntaxError
# for = 3           -> SyntaxError
```

## Exam traps checklist {#traps}

- `x += 1` on a global inside a function without `global x` → `UnboundLocalError`.
- An assignment *anywhere* in a function makes the name local in the *whole* function.
- Reading a global inside a function is fine and uses its value at call time.
- `global` targets module level; `nonlocal` targets the enclosing function; `nonlocal` on a name the enclosing function declared `global` → `SyntaxError`.
- Loop variables and variables created in `if`/`for` blocks survive the block.
- `def` does not execute the body; calling a function above its `def` → `NameError`.
- `b = a` is an alias, not a copy; rebinding `a` afterwards does not change `b`.
- Mutating a parameter is visible to the caller; rebinding it is not.
- `a += [x]` mutates the list (aliases see it); `a = a + [x]` creates a new list.
- `+=` on a str/tuple/int creates a new object.
- `t[0] += [1]` on a tuple holding a list: the list is extended, then `TypeError`.
- Mutable default argument (`acc=[]`) is shared between calls; use `None`.
- Shallow copies (`[:]`, `list()`, `.copy()`, `copy.copy`) share nested lists; use `copy.deepcopy`.
- `[[0] * 3] * 3` → three references to one row.
- `[lambda: i for i in range(3)]` → every lambda returns 2 (late binding).
- `run(f(3), 4)` passes a value, not a function → `TypeError`.
- No reachable base case → `RecursionError`; forgetting `return` on the recursive call → `None`.
- `is` checks identity, `==` checks value; use `is None`; never rely on `is` with small ints/strings.
- `list`, `print`, `sum` can be rebound (then calling them fails); `None`, `True`, `for` cannot (SyntaxError).
